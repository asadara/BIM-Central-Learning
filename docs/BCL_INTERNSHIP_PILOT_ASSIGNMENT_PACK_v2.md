# BCL BIM Internship Pilot — Participant Assignment Pack v2

Status: **PROPOSED — NOT YET RELEASED**
Applies to: proposed manifest `INT-BIM-PILOT-MANIFEST-v3`

## Before You Start

Complete the required learning shown in the approved v3 path, then wait for your mentor to release each exercise and its sanitized or synthetic case data. Work in the locally approved BIM tools. Do not upload native project models, source code, executables, credentials, confidential project data, or internal storage paths.

For each assignment, your mentor makes the acceptance decision. Rubric scores explain quality but do not automatically accept or reject a submission. If revision is requested, submit a new revision against the same assignment.

Evidence limits: maximum five files, maximum 10 MiB per file, using PDF, DOCX, XLSX, CSV, JPG/JPEG, or PNG as allowed by the individual brief.

## 1. Model Quality & Information Review

Review the supplied model against the mentor-approved checklist. Inspect structure, naming, levels/grids, parameters, completeness, drawing/QTO readiness, and important data-quality risks.

Submit:

- PDF model-quality review;
- XLSX/CSV QA/QC findings checklist;
- optional annotated JPG/PNG screenshots.

Acceptance requires traceable findings, sensible severity/priorities, reproducible review logic, and corrective recommendations for all critical issues.

## 2. Federated Model Coordination & Clash Review

Verify the supplied ARS/STR/MEP exercise files, coordinate assumptions, units, alignment, test scope, and tolerances. Group and prioritise meaningful issues, recommend ownership/actions, and document recheck status.

Submit:

- PDF coordination report;
- XLSX/CSV clash and issue log;
- representative JPG/PNG screenshots.

Acceptance requires technically useful issue classification and clear traceability between evidence, status, ownership, and recommended action.

## 3. 4D Model–Schedule Linkage

Interpret the supplied WBS and schedule, define model grouping and common-ID rules, map model groups to activities, validate missing/duplicate/format problems, and review sequence logic.

Submit:

- PDF 4D workflow and validation report;
- XLSX/CSV model–activity/common-ID mapping;
- JPG/PNG sequence-review screenshots.

Acceptance requires coherent IDs, grouping, mapping, validation, sequence reasoning, and clearly documented corrections.

## 4. QTO / 5D Validation

Check model and parameter readiness for the assigned quantity scope. Produce a controlled extract, compare it with the supplied BOQ/reference, reconcile differences, and explain reliability limitations.

Submit:

- XLSX/CSV quantity extract and reconciliation;
- PDF methodology and discrepancy report;
- optional JPG/PNG supporting screenshots.

Acceptance requires a reproducible method and transparent treatment of discrepancies and reliability risks.

## 5. Automation / Digital Workflow Improvement

This is a required v3 assignment with operational gates. Do not begin until the mentor approves the problem, non-confidential baseline, local toolchain, feedback users, and external source/release-governance boundary.

Audit a repetitive BIM/data workflow, define its information architecture and controls, prototype locally, validate error cases, benchmark time/steps/errors/repeatability, collect feedback, revise once, and document safe use and handover. Source code and executables remain in the separately approved external repository; they are not BCL uploads.

Submit:

- PDF/DOCX technical improvement and architecture report;
- XLSX/CSV benchmark and validation dataset;
- PDF/DOCX governance, SOP, feedback, and external release record;
- JPG/PNG before/after workflow evidence.

Acceptance requires a useful and repeatable result, measurable benefit, validated outputs, a feedback-driven revision, explicit limitations, and traceable external release governance.

## 6. BIM Documentation, Governance & Handover Package

Prepare the controlled delivery and handover record for the approved exercise outputs. Cover naming/status/authority, revisions/issues, consistency, applicable tool documentation and SOP, limitations, responsibilities, knowledge transfer, remaining backlog, and final presentation.

Submit:

- PDF/DOCX governance, documentation, and handover narrative;
- XLSX/CSV deliverable/revision/issue/backlog register;
- PDF final presentation and mentor sign-off record.

Acceptance requires a package another team member can understand and continue safely, with clear status, responsibilities, limitations, open actions, and closeout evidence.

## Activities That Are Not Separate Required Assignments

Mentor observation, guided Synchro/dashboard exposure, technical research, innovation discussion, user feedback sessions, and presentation activities may support the six assignments. They do not create additional completion requirements unless a later approved manifest explicitly changes the denominator.

The final capstone remains excluded from this pilot version.
